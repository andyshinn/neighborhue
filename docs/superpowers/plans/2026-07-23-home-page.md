# Home Page (Spec 2d) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder at `/` with the real marketing Home page — nav, hero with an example share-card over a breathing glow, "How it works", a Home Assistant band, and a footer.

**Architecture:** The route is the only data-toucher: it fetches palettes (failure-tolerant, since the data is decorative), derives a `HeroPalette`, and hands it to props-driven components. Three shipped primitives gain small backward-compatible extensions so the hero can reuse them (`usePaletteCycle`, `SwatchRow`, `ShareCard`), and the lockup markup duplicated across Create and Manage is extracted into `SiteLogo`.

**Tech Stack:** TanStack Start (Vite + React 19 + Router) + TanStack Query, Radix Primitives (`Collapsible`) + Radix Icons + Radix Colors, CSS Modules over `tokens.css`, Vitest + Testing Library + happy-dom.

**Spec:** [`docs/superpowers/specs/2026-07-23-home-page-design.md`](../specs/2026-07-23-home-page-design.md) — decisions are cited as H1–H12.

## Global Constraints

- **No API change.** This spec adds no endpoint, type, or field. `GET /v1/palettes` is consumed exactly as it exists (spec §3.2).
- **Copy is verbatim.** Every user-facing string is fixed in spec §9 and reproduced in the tasks below. Do not paraphrase, re-punctuate, or "improve" it.
- **Never compute the daily color client-side.** The hero shows a representative palette color; it is an illustration, never a claim about today (H1).
- **No `tabIndex` on the example card** (H5). The card holds no interactive controls; adding a focus stop would trip Biome's `noNoninteractiveTabindex` and do nothing for assistive tech.
- **`ShareCard`'s static branch forwards the raw `activeHex` prop, never the derived `highlight`** (H11) — `highlight` falls back to `activeColor.hex`, which would silently add a highlight to Manage's preview swatches.
- **Any new Radix accent step must be re-declared in `tokens.css`'s `@media (prefers-color-scheme: dark)` block**, or dark mode silently falls back to the light value (that file documents the rule).
- **Reduced motion:** no new animation or transition may run under `prefers-reduced-motion: reduce`.
- **Existing behavior is frozen:** Create and Manage must render and test exactly as they do today. New parameters default to current behavior.
- Text apostrophes use the plain `'` (matching the existing components).
- Commands: `pnpm -F @neighborhue/web test`, `pnpm -F @neighborhue/web typecheck`, `pnpm check` (Biome, from the repo root).

// Walks 0..length-1 on a timer so the Create preview reads as a sample reel
// ("one of these, chosen each day"), never a fixed "today". Honors
// prefers-reduced-motion (C11) and resets when the palette (length) changes.
// `enabled` gates the timer for Home's hover-only cycle (2d H12); it defaults
// to true so Create's always-on call is unchanged.
export function usePaletteCycle(length: number, intervalMs: number = DEFAULT_INTERVAL_MS, enabled = true): number {
  const [index, setIndex] = useState(0)

  useEffect(() => {
    setIndex(0)
    if (!enabled || length <= 1 || prefersReducedMotion()) return
    const id = setInterval(() => setIndex((i) => (i + 1) % length), intervalMs)
    return () => clearInterval(id)
  }, [length, intervalMs, enabled])

  return length > 0 ? index % length : 0
}
```

// The Home hero's example card (2d H1). It is an illustration drawn from the
// real default palette — never a claim about today's color, which only the
// server can choose. Returns null when there is nothing safe to draw: no
// palettes (the fetch is allowed to fail, H9) or a palette with no colors.
export interface HeroPalette {
  name: string
  colors: PaletteColor[]
}

export function toHeroPalette(palettes: PaletteSummary[]): HeroPalette | null {
  const summary = palettes.find((p) => p.is_default) ?? palettes[0]
  if (!summary || summary.colors.length === 0) return null
  return { name: summary.name, colors: summary.colors }
}
```

import type { HeroPalette } from '../lib/palette'
import styles from './HomeHero.module.css'

interface HomeHeroProps {

// (pure red) at hero scale. Matched by hex, not index, so reordering the
// palette cannot silently change it; index 0 is the fallback if it is removed.
const RESTING_HEX = '#0080FF'
const EXAMPLE_NAME = 'Maple Street'

### Task 9: Wire the `/` route

**Files:**
- Modify: `apps/web/src/routes/index.tsx` (replaces the placeholder entirely)

**Interfaces:**
- Consumes: `toHeroPalette(palettes)` (Task 4), `HomeView` (Task 8), the existing `palettesQueryOptions()` from `lib/queries.ts`.
- Produces: the `/` route. This is the last task; after it, `/` serves the real page.

The route keeps SSR (the default) so the hero paints with zero JS and the OG tags unfurl. The palettes fetch is **decorative** (H1/H9): the loader swallows its error and the component reads with a non-suspense `useQuery`, so a palettes outage degrades to a copy-only hero instead of a 500 on the marketing page.

**On testing:** spec §7 asks for a route test covering three cases — palettes resolve, the fetch rejects, and the default palette has no colors. No route in this codebase has a unit test (testing a TanStack file route needs router scaffolding for little value), so that coverage is split into pure units instead: `toHeroPalette` is tested against all three inputs in Task 4, and `HomeHero` is tested with `palette={null}` — the exact state a rejected fetch produces. The route itself is four lines of wiring, verified end-to-end by Step 3's SSR check. This is a deliberate deviation, not a gap.

- [ ] **Step 1: Replace the route**

Replace the entire contents of `apps/web/src/routes/index.tsx`:

```tsx
import { useQuery } from '@tanstack/react-query'
import { createFileRoute } from '@tanstack/react-router'
import { HomeView } from '../components/HomeView'
import { toHeroPalette } from '../lib/palette'
import { palettesQueryOptions } from '../lib/queries'

const DESCRIPTION =
  'Neighborhue gives your street one shared color that changes every morning. Point your smart lights at a single link and the whole block lights up together.'

// SSR (route default): the hero paints with zero JS and the OG tags unfurl.
// The palettes fetch only feeds the example card, so its failure must not take
// the marketing page down (spec H9) — the loader swallows the error and the
// component reads with a non-suspense useQuery, falling back to a copy-only hero.
export const Route = createFileRoute('/')({
  loader: async ({ context }) => {
    try {
      await context.queryClient.ensureQueryData(palettesQueryOptions())
    } catch {
      // decorative: the hero renders without its example card
    }
  },
  head: () => ({
    meta: [
      { title: 'Neighborhue — the whole neighborhood glows the same color' },
      { name: 'description', content: DESCRIPTION },
      { property: 'og:title', content: 'The whole neighborhood glows the same color.' },
      { property: 'og:description', content: DESCRIPTION },
    ],
  }),
  component: Home,
})

function Home() {
  const { data } = useQuery(palettesQueryOptions())
  return <HomeView palette={toHeroPalette(data ?? [])} />
}
```
